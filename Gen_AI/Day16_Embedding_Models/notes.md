# Day 16 — Embedding Models

## 1. What is an embedding model?

An embedding model converts text into dense numerical vectors that capture useful semantic information.

Example:

```text
Input:
"Customer failed to repay the loan."

Output:
[0.21, -0.45, 0.78, 0.12, ...]
```

The values above are illustrative.

The objective is to represent text in a vector space where semantically similar text can have nearby representations.

Example:

- "Customer failed to repay the loan."
- "Borrower missed the scheduled loan payment."

Although the wording differs, the sentences have similar meanings.

## 2. How does an embedding model work?

High-level pipeline:

```text
Input Text
    ↓
Tokenisation
    ↓
Token IDs
    ↓
Token Embeddings
    ↓
Transformer Encoder
    ↓
Pooling
    ↓
Sentence Embedding
```

### Step 1: Tokenisation

Converts text into smaller units called tokens.

### Step 2: Token embeddings

Maps token IDs into numerical vectors using an embedding layer.

### Step 3: Transformer encoder

Processes token representations and captures contextual relationships using attention and other Transformer layers.

### Step 4: Pooling

Combines token-level representations into a single fixed-dimensional vector representing the entire sentence or passage.

Common pooling methods:

- Mean pooling: averages token representations.
- CLS pooling: uses the representation associated with the `[CLS]` token.
- Max pooling: takes the maximum value across token representations in each dimension.

The correct pooling strategy depends on the embedding model's architecture and training.

## 3. What is contextual representation?

The meaning of a word can depend on the surrounding words.

Example:

```text
Sentence 1:
The bank approved the loan.

Sentence 2:
He sat beside the river bank.
```

The word `bank` has different meanings in these sentences.

A Transformer produces contextual token representations using the surrounding context.

WordPiece tokenisation itself does not understand contextual meaning; contextual representations are generated by the Transformer.

## 4. Embedding model vs Generative LLM

| Embedding model | Generative LLM |
|---|---|
| Converts text into vectors | Generates text |
| Used for semantic search | Used for answering and generation |
| Produces embedding vectors | Produces token probabilities and generated output |
| Supports retrieval | Supports generation and reasoning |

In a RAG application:

- The embedding model represents queries and documents as vectors.
- The retrieval mechanism finds relevant document chunks.
- The LLM uses the retrieved context to generate an answer.

These models have separate responsibilities and can be different models.

## 5. Document embeddings vs Query embeddings

Both documents and user queries are converted into vectors for semantic comparison.

Example:

```text
Document:
Customers must repay their loans within
the agreed repayment period.

Query:
What happens if a borrower misses a payment?
```

Processing:

```text
Document → Document Embedding
Query    → Query Embedding
                ↓
       Similarity Comparison
                ↓
       Relevant Document Retrieval
```

Important requirements:

- Query and document vectors must have compatible dimensions.
- They should belong to compatible embedding spaces.
- Usually, the same model is used for both.
- Some retrieval models require different query/document prefixes or encoding methods. Follow the model's instructions.

## 6. Embedding dimensions

Embedding dimension represents the number of numerical values in a vector.

Examples:

- 384 dimensions = 384 numerical values.
- 768 dimensions = 768 numerical values.
- 1536 dimensions = 1536 numerical values.

Higher dimensions do not automatically mean better semantic retrieval.

Model architecture, training data, training objectives and suitability for the task matter.

Higher dimensions also increase storage and computational requirements.

## 7. Important embedding models

| Model | Characteristic |
|---|---|
| `all-MiniLM-L6-v2` | Lightweight general-purpose sentence embeddings |
| `all-mpnet-base-v2` | General-purpose sentence embeddings |
| `BAAI/bge-base-en-v1.5` | Retrieval-focused embedding model |
| `intfloat/e5-base-v2` | Retrieval model with query/passage conventions |
| `nomic-embed-text` | Embedding model with long-context variants |

For our learning project, we used `all-MiniLM-L6-v2`.

For an enterprise banking deployment, model selection must also consider:

- Data privacy and security.
- Licensing.
- Language and domain coverage.
- Retrieval quality.
- Latency and throughput.
- Hardware requirements.
- Evaluation on representative banking documents.

These are model-selection considerations, not claims about an existing SBI deployment.

## 8. Practical implementation

File:

`16-Embedding-Models/practical/generate_embeddings.py`

Installation:

```bash
pip install sentence-transformers
```

Implementation:

```python
from sentence_transformers import SentenceTransformer, util

# Load embedding model
model = SentenceTransformer("all-MiniLM-L6-v2")

sentences = [
    "Customer failed to repay the loan.",
    "Borrower missed the scheduled loan payment.",
    "The weather is pleasant today."
]

# Generate embeddings
sentences_embeddings = model.encode(sentences)

# Print embedding shape
print("Embedding shape:", sentences_embeddings.shape)

# Print first sentence embedding
print("First embedding:", sentences_embeddings[0])

# Compare first two sentences
similarity_1_2 = util.cos_sim(
    sentences_embeddings[0],
    sentences_embeddings[1]
)

# Compare first and third sentences
similarity_1_3 = util.cos_sim(
    sentences_embeddings[0],
    sentences_embeddings[2]
)

print("Similarity (1 vs 2):", similarity_1_2)
print("Similarity (1 vs 3):", similarity_1_3)
```

- Total values = 3 × 384 = 1,152.

Each sentence receives its own vector.

### Cosine similarity results

| Comparison | Result |
|---|---:|
| Loan repayment vs missed payment | 0.64909804 |
| Loan repayment vs weather | -0.048483685 |

Interpretation:

- The first two sentences have relatively strong semantic similarity.
- The first and third sentences have very low similarity.

A similarity score is not a probability or a guarantee of identical meaning.

## 10. Cosine similarity

Cosine similarity compares the angle between two vectors.

Formula:

```text
                 A · B
Cosine Similarity = -----------
                   ||A|| ||B||
```

Interpretation:

| Score | Meaning |
|---|---|
| +1 | Same direction |
| 0 | Orthogonal directions |
| -1 | Opposite directions |

A negative similarity does not necessarily mean two sentences have opposite meanings.

## 11. Important distinctions

| Concept | Responsibility |
|---|---|
| Embedding generation | Converts text into vectors |
| Similarity calculation | Compares two vectors |
| Similarity search | Ranks candidate vectors against a query |
| Vector database | Stores and retrieves vectors efficiently |

These are separate operations in a retrieval pipeline.

## 12. Key takeaways

1. Embedding models convert text into dense vectors.
2. Transformer encoders generate contextual token representations.
3. Pooling combines token representations into a sentence vector.
4. Sentence embeddings are useful for semantic search and RAG.
5. Embedding models and generative LLMs have different responsibilities.
6. Query and document embeddings must be compatible.
7. Embedding dimensions indicate vector size, not quality.
8. Cosine similarity measures directional similarity between vectors.
9. Similarity scores are not probabilities.
10. Model selection requires task-specific evaluation.
